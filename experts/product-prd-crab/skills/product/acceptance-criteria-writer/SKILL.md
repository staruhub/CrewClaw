# Acceptance Criteria Writer

## Overview

Translate product intent into criteria that engineering and QA can verify.

## When to Use

Use when a PRD has goals but lacks measurable completion criteria.

## Workflow

1. Restate the expected user behavior.
2. Define preconditions and triggers.
3. Define successful outcomes.
4. Define failure outcomes.
5. Write criteria in observable language.

## Common Pitfalls

- Do not use criteria like "works well".
- Do not hide important conditions in prose.
- Do not make implementation choices unless required by the requirement.

## Verification Checklist

- [ ] Each criterion is testable.
- [ ] Success and failure states are included.
- [ ] Ambiguous adjectives are removed.
