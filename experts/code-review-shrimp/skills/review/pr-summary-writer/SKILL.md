# PR Summary Writer

## Overview

Write a short summary that helps reviewers and stakeholders understand a change.

## When to Use

Use after reading a PR, local diff, or review notes.

## Workflow

1. State what changed.
2. State why it changed.
3. List verification evidence.
4. Name remaining risks.
5. Keep the tone factual.

## Common Pitfalls

- Do not turn uncertainty into certainty.
- Do not omit failed checks.
- Do not include implementation trivia unless it affects risk.

## Verification Checklist

- [ ] Summary is understandable without reading every file.
- [ ] Risks and failed checks are visible.
- [ ] No unsupported claims are included.
